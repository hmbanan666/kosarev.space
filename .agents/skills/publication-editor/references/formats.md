# Format guidance

Load this reference only for drafting, revising or selecting the publication format.

## Note

One observation, question or idea; a short paragraph or several can be enough.
Lead with the thought, give just enough context and, where applicable, an example
or source. It need not pretend to be a complete investigation. Avoid padding,
forced takeaways and filler headings. Separate untested hunches from findings.

## Digest

A **curated set of developments with the author's judgement**, not an
automatically generated news summary.

- Select for relevance to builders of products, AI tooling and open source.
  A pilot could include one main development and three or four finds, but this
  is not a required quota.
- Each selected item: what happened, dated **primary source** (release,
  documentation, issue or PR), why it matters practically, known caveat, and
  concise author commentary when the author has a view.
- Distinguish shipped changes from proposals and active discussions. Verify
  dates and versions at writing time; don't claim an issue is a release.
- An optional "what I tried" section needs an actual author experiment.
  A model must not manufacture personal testing or imply endorsement.
- One weekly issue can be tried as an experiment; do not promise a recurring
  schedule or create newsletters, auto-posting or feeds without approval.

## Article / deep dive

A single worthwhile problem or insight can support a long analysis or a short
article. Explain the stakes for the intended reader before diving into code
or implementation. Concrete evidence, alternatives, surprising observations
and limitations support the author's conclusion.

If material is primarily a how-to for this repository, label it documentation
and consider linking it from a shorter public article. Link to a project page
for the product and a case page for a delivery record rather than repeating them.

## All formats

One chronological Writing stream; format is optional metadata, not a separate
site or database. Relate articles to projects/cases without making publication
depend on a project. Do not add categories, filters or a content platform solely
to classify the first piece.

The author chooses publication. Drafting in English or Russian does not authorize
publishing the other language or releasing private material.
